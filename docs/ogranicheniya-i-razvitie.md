# Ограничения решения и план развития

## Ограничения

### Данные

| Ограничение | Последствие | Как учли |
|---|---|---|
| Нет остановки входа (`place_id` — площадка депо) | Прогноз на уровне «маршрут × час», по остановкам — только оценка | Честная пометка «оценка» в интерфейсе |
| Нет выходов пассажиров | Нельзя посчитать наполняемость вагона в % | Показываем «пассажиров в час» и «пассажиров на трамвай» |
| Нет телематики (GPS) | Нет фактических скоростей и задержек трамваев | Число трамваев на линии считаем по номерам выходов в валидациях |
| Данные за 10 месяцев (январь–октябрь 2025) | Годовая сезонность видна частично, ноября–декабря прошлых лет нет | Горизонт — до двух месяцев; год не заявлен |
| Маршрут 5 без данных | Исключён организаторами | Прогноз 0, в интерфейсе «нет данных» |
| Нет координат маршрутов 17, 25, 26, 28, 50 в справочнике | Не рисуются на карте | Показываются в списках и таблицах; координаты можно взять из открытых данных |
| Расписание и наряды — только образцы | Нет плановых выходов и вместимости вагонов | Норма пассажиров на трамвай — настраиваемый параметр (150) |
| Ночные валидации технологические | Искажают обучение | Исключены из обучения |
| Хэш карты нестабилен при оплате телефоном | Нельзя надёжно считать уникальных пассажиров и цепочки поездок | Хэш в модели не используется |

### Модель

| Ограничение | Последствие |
|---|---|
| Вклад части внешних источников (трафик, события, ДТП) на проверке не подтверждён | Их эффект может быть случайным; ключевой вклад дают история потока и календарь |
| Погода — климатическая норма, а не прогноз на конкретный день | Модель не реагирует на погоду конкретного дня |
| Проверочный период использовался при подборе модели | Оценка на нём может быть немного оптимистичной |
| Модель не видела ремонтов и перекрытий как отдельного фактора | В такие дни прогноз завышен |

### Продукт

| Ограничение | Последствие |
|---|---|
| Предложения по перераспределению выходов — эвристика по норме пассажиров на трамвай | Не учитывает связность путей и смены водителей; переброска только в пределах одного депо |
| При изменении числа трамваев поток считается неизменным | Не учитывается рост спроса при более частом движении |
| Реального потока данных нет | Режим «реального времени» — воспроизведение исторического дня |
| Авторизация базовая | Для промышленной эксплуатации нужна интеграция с корпоративной системой доступа |

## План развития после хакатона

### Ближайший месяц

1. **Прогноз по остановкам и участкам** — получить полное расписание и наряды, привязать валидации к остановке по номеру выхода и времени.
2. **Погода на конкретный день** — архив и прогноз погоды Open-Meteo вместо климатической нормы.
3. **Восстановление провалов в данных** — автоматический поиск перебоев валидации и заполнение по аналогичным периодам.
4. **Ремонты и перекрытия** как фактор модели — загрузка плановых работ из открытых городских источников.
5. **Автоматическое переобучение** — модель переобучается по расписанию, новая версия включается после проверки качества.

### Три месяца

1. **Загрузка вагона в процентах** — оценка выходов через пересадки при получении валидаций метро и МЦК с тем же хэшем карты; вместимость вагонов из нарядов.
2. **Телематика (GPS)** — фактические скорости и задержки трамваев как признак загруженности улиц.
3. **ИИ-агент сбора событий** — автоматическое чтение афиш, календарей матчей и новостей о закрытиях метро с подтверждением человеком.
4. **Горизонт «год»** — сезонные сценарии после накопления данных за полный год.
5. **Интеграция с депо** — передача решения о выпуске вагона и отметка исполнения.

### Масштабирование

1. **Все трамвайные маршруты Москвы** и другие виды наземного транспорта (автобусы, электробусы) — тот же пайплайн и формат данных.
2. **Потоковая обработка** валидаций в реальном времени (очередь сообщений, колоночное хранилище ClickHouse для истории).
3. **Мониторинг качества прогноза** — сравнение прогноза с фактом каждый день и оповещение о росте ошибки.
