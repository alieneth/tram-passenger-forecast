# Q&A с экспертами — 26.09.2026

Главное из Q&A-сессии по треку «ИИ-прогноз загрузки трамвайных маршрутов». Полная расшифровка — в пакете команды (`14_qa-sessiya/`).

## Модель и данные

| Тема | Ответ экспертов | Что делаем |
|---|---|---|
| Точность выше 0,88 | Максимум баллов за метрику уже есть, но «чем точнее модель, тем больше шансов на лидирующую позицию» | Улучшаем скор, пока есть время |
| Утечка данных | В рамках хакатона не проверяют, баллы не снимают | Фактическую погоду ноября–декабря использовать можно — решение за ML |
| Маршрут 5 | «Предложение отказаться от пятого маршрута — проблемы при выгрузке данных»; оцениваются 9 маршрутов | Прогноз 0, в интерфейсе «нет данных» |
| Сколько маршрутов на платформе | 10 маршрутов из датасета | Показываем все, прогнозируем 9 |
| Ночные часы | Валидации в нерабочие часы (≈01:00–05:30) — технологические (проверка оборудования) — «отфильтруйте» | Исключаем из обучения, прогноз ночью 0 |
| Провалы в данных | Бывают из-за ремонтов или потери связи с оборудованием; восстановление по аналогичным периодам — «большой плюс» | Найти и восстановить провалы |
| Что считается пассажиропотоком | Все успешно провалидированные транзакции, включая разные способы оплаты | boardings = validation_result = 1 |
| Колонка пересадок | Стоимостная характеристика для взаиморасчётов между перевозчиками, на поток не влияет | Смысла как у фактора не придаём |
| Хэш карты | Нестабилен при оплате телефоном (NFC генерирует разные указатели) | Уникальных пассажиров и цепочки поездок по нему не считаем |
| Формат прогноза | Целое число, округление до ближайшего | Округляем |
| Расписания | Можно брать из открытых источников — «только на плюс» | Трассы маршрутов без координат — из открытых данных |

## Горизонты и агрегация

- Минимальный шаг — час: в пределах суток — по часам.
- Неделя — по дням, месяц — по дням («нужно понимать, как изменяются пики»).
- Год — по желанию, за дополнительные баллы; интересно, как модель ведёт себя при неполной информации. Долгий прогноз можно считать асинхронно.

## Сервис и интерфейс

- **Базовая авторизация желательна**, в том числе межсервисная. Логин и пароль для жюри — отдельным файлом.
- У контейнеров при проверке жюри будет интернет — внешние данные можно подгружать.
- Интерфейс — элемент системы диспетчеризации; стандартные экраны диспетчеров.
- **Сплит**: карта и графики / таблицы в одном интерфейсе, быстрое переключение представлений.
- Оперативность: из общей прогностической картины дня за минимум действий перейти в развёртку конкретного маршрута, дальше — на неделю и месяц, **не теряя контекста** (однозначно видно, с каким объектом работаешь).
- Однозначность считывания: цветовая индикация, обозначения трамваев читаются при любом масштабе.
- Управляющие элементы — в одной области, минимум движений.
- Тёмная подложка рекомендована. Адаптивность — не в минус.
- Что показывать диспетчеру — на усмотрение команды, но за внешние источники информации есть отдельные баллы.
