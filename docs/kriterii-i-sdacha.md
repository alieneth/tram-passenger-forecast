### 1. Качество прогноза (0–5 с весом 2)

WAPE-score = max(0, 1 − Σ|y − ŷ| / Σy), от 0 до 1, больше — лучше. Baseline ≈ 0,48 — «пол», который нужно превзойти.

| WAPE-score | Баллы | С учётом веса |
|---|---|---|
| ≤ 0,48 | 0 | 0 |
| 0,48–0,60 | 1 | 2 |
| 0,60–0,70 | 2 | 4 |
| 0,70–0,80 | 3 | 6 |
| 0,80–0,88 | 4 | 8 |
| > 0,88 | 5 | 10 |

### 2. Данные, внешние источники и область применимости (0–8)

- **а) Внешние источники — до 4 баллов**, по 1 за использованный и подтверждённый эффектом источник:
  - дорожный трафик / загруженность улиц;
  - погода (температура, осадки и т. п.);
  - сезонность и календарь (выходные, праздники РФ/Москвы, каникулы, сезонное переключение спроса);
  - прочие внешние факторы (события, новости, перекрытия, ремонты).
  - **Обязательно: на каждый источник — рабочая ссылка или способ получения. Без ссылки не засчитывается.**
- **б) Область определения и адаптации модели — до 2 баллов**: на каких маршрутах, горизонтах, диапазонах данных модель валидна; от каких внешних данных зависит; что нужно для переноса на новые маршруты и периоды. Явно описаны пределы применимости.
- **в) Корректирующие коэффициенты — до 2 баллов**: в интерфейсе можно менять поправку на погоду / событие / сезон и сразу видеть изменение прогноза (+1); корректная агрегация целевой величины и воспроизводимый пайплайн приёма данных (+1).

### 3. Архитектура и производительность (0–5)

- Соответствие общим архитектурным принципам.
- Читаемое разделение на модули: приём/нормализация данных → признаки/геопривязка → ML-прогноз/агрегация → API → frontend.
- REST/HTTP API отдаёт прогноз по параметрам: маршрут, остановка/участок, интервал, горизонт.
- Производительность и масштабируемость — по заявленным командой метрикам (latency/RPS в README); отдельный нагрузочный тест жюри не проводит, честная оценка с подтверждением засчитывается.
- **Без запускаемого сервиса балл существенно снижается.**

### 4. Полнота функциональности (0–4)

- Горизонты: день обязателен; месяц и год — хотя бы качественно (по ответу организаторов в чате год — по желанию).
- Агрегация: по маршруту, остановке/участку, интервалу времени.
- Интерактивный дашборд с картой Москвы: динамика пассажиропотока по времени и точкам маршрута.
- Выгрузка прогноза в CSV и/или XLSX.

### 5. Бизнес-ценность и применимость (0–2)

- Показано применение: распределение подвижного состава, снижение переполнения салонов, уточнение расписания, оптимизация эксплуатации.
- Реалистичность выводов и понимание ограничений решения.
