# Инструкция для жюри

Сервис прогноза пассажиропотока трамваев. Ниже — как запустить его за несколько минут и что посмотреть.

## 1. Что нужно

- Docker и Docker Compose (Docker Desktop на macOS / Windows или Docker Engine на Linux).
- Свободные порты: 5433 (база данных), 8080 (API), 3000 (интерфейс диспетчера).
- Интернет при первом запуске — только для скачивания базовых образов (Postgres, Maven, Node,
  JRE) и сборки. Данные для демо (справочник, факт, календарь, погода, прогноз на ноябрь–декабрь
  2025) уже лежат в образе БД и не тянутся из сети.
- Около 4 ГБ свободного места (образы + сборка).

## 2. Запуск

```bash
git clone https://github.com/alieneth/tram-passenger-forecast.git
cd tram-passenger-forecast
cp .env.example .env
docker compose up -d
```

Первый запуск занимает 10–15 минут (зависит от скорости интернета — дольше всего собирается
фронтенд, там много npm-зависимостей); повторные — секунды. Собираются образы, создаётся база
данных, автоматически загружаются готовые данные (справочник маршрутов, почасовой факт, календарь,
погода, прогноз на ноябрь–декабрь 2025) — никаких дополнительных команд после `docker compose up -d`
не требуется. Полный датасет (10 ГБ) для проверки не нужен.

Проверка, что всё работает:

```bash
curl http://localhost:8080/api/v1/health
```

Ответ `"status": "UP"` — сервис готов и прогноз рассчитан.

## 3. Вход

| Что | Адрес | Логин / пароль |
|---|---|---|
| Интерфейс диспетчера | http://localhost:3000 | Без входа — интерфейс открыт, отдельного логина нет |
| Документация API (Swagger) | http://localhost:8080/swagger-ui/index.html | — |
| Контракт API | `docs/openapi.yaml` | — |

Два метода контракта требуют Bearer-токен (`POST /validations` — приём данных, `GET/PATCH
/decisions` — решения диспетчера): значения — переменные окружения `AUTH_INGEST_TOKEN` и
`AUTH_DISPATCHER_TOKEN` в `.env` (по умолчанию `change_me_ingest`/`change_me_dispatcher`, если не
переопределены). Реальные значения для боевого стенда — не в этом файле, по отдельному защищённому
каналу от команды.

## 4. Что посмотреть за 5 минут

1. **Обзор** — прогноз на 14.11.2025 по всем маршрутам: карта и таблица «маршруты × часы», факторы дня.
2. **Маршрут** — выбрать маршрут: прогноз по часам с коридором уверенности, переход на неделю и месяц, вклад факторов.
3. **Карта** — «Проиграть день»: как меняется поток по маршрутам в течение суток.
4. **Что если** — изменить поправки на погоду, событие, сезон и увидеть пересчёт прогноза.
5. **Решения** — предложения по перераспределению трамваев при превышении нормы. Список сейчас пуст:
   реального числа трамваев на линии нет ни в прогнозе, ни в загруженных данных — генератор решений
   работает честно и не выдумывает несуществующие перегрузки (подробности — `backend/README.md`).
6. **Качество модели** — WAPE-score и ошибка нашей модели против базовой на сентябре–октябре 2025.
7. **Экспорт** — выгрузка прогноза в CSV / XLSX и в формате сабмита.

## 5. Примеры запросов к API

```bash
# Список маршрутов
curl http://localhost:8080/api/v1/routes

# Прогноз маршрута 17 на 14.11.2025 по часам
curl "http://localhost:8080/api/v1/forecast?route=17&date_from=2025-11-14&horizon=day"

# Прогноз по дням на ноябрь
curl "http://localhost:8080/api/v1/forecast?route=17&date_from=2025-11-01&date_to=2025-11-30&horizon=month"
```

Все методы, параметры и коды ошибок — в Swagger и `docs/openapi.yaml`.

## 6. Если что-то не запустилось

| Симптом | Что сделать |
|---|---|
| Порт занят | Поменять порт в `.env` и перезапустить `docker compose up -d` |
| `/health` отвечает `DOWN` | База ещё стартует — подождать минуту; логи: `docker compose logs db` |
| `/health` отвечает `DEGRADED` | Активной версии модели нет — данные не накатились на пустой volume; пересоздать: `docker compose down -v && docker compose up -d` |
| Нужна полная загрузка датасета | Положить `train.csv`/`test.csv` в `data/` и выполнить `docker compose run --rm loader` — см. `backend/db/README.md` |
