# ИИ-прогноз пассажиропотока трамваев

Хакатон Московского транспорта, трек «ИИ-прогноз загрузки трамвайных маршрутов».
Заказчик — ЕДЦ ГУП «Московский метрополитен».

Веб-сервис прогнозирует число входов пассажиров по трамвайному маршруту на каждый час (горизонты «День» и «Месяц»), показывает тепловую карту Москвы, отдаёт прогнозы через REST API и выгружает их в таблицы. Для диспетчера — предложения по перераспределению трамваев между маршрутами.

> Статус: в разработке. Разделы «Запуск», «API» и «Производительность» заполняются по мере готовности.

├── frontend/       — дашборд на React

## Архитектура (кратко)

```
валидации + внешние факторы → ml/ (Python: обучение и пакетный прогноз) → БД (таблица прогнозов)
                                                                         ↓
                                     frontend/ (React) ← REST API ← backend/ (Java: только чтение)
```

Прогнозы считаются заранее — поэтому API быстрый (цель p95 < 300 мс).

## Запуск

```bash
cp .env.example .env
docker compose up -d
```

API поднимется на `http://localhost:8080/api/v1`, PostgreSQL — на `localhost:5433` (5432 на хосте
часто занят другим локальным Postgres). Схема и демо-данные (справочник, факт, календарь, погода,
прогноз на ноябрь–декабрь) накатываются автоматически при первом запуске на пустом volume —
никаких ручных команд не нужно.

Полные сырые валидации (~62 млн строк, опционально — см. [`backend/db/README.md`](backend/db/README.md)):

```bash
docker compose run --rm loader
```
