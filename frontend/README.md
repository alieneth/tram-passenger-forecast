# frontend — дашборд (Сергей)

React 19, TypeScript 5 (strict), Vite, Prettier + ESLint, TanStack Query, React Router, карта — MapLibre GL, графики — Recharts. См. раздел 11 в `/CLAUDE.md`.

## Запуск

### В Docker вместе со всем сервисом

Фронт собирается в образ `frontend/Dockerfile`: сборка Vite → nginx, который отдаёт статику и
проксирует `/api` на бэкенд (`API_UPSTREAM`, по умолчанию `http://backend:8080`) — один адрес, без CORS.
Сервис в корневом `docker-compose.yml`:

```yaml
frontend:
  build:
    context: ./frontend
  environment:
    API_UPSTREAM: http://backend:8080
  ports:
    - '${FRONTEND_PORT:-3000}:80'
  depends_on:
    - backend
```

После `docker compose up --build` интерфейс — http://localhost:3000, Swagger бэкенда — http://localhost:3000/swagger-ui.

**Гибридный режим** (в образе включён по умолчанию, `VITE_MOCK_FALLBACK=true`): методы, которые бэкенд
ещё не отдаёт (501, недоступен, «прогноз ещё не рассчитан», пустой справочник маршрутов), берутся из
моков, в шапке значок «Частично мок: …» со списком таких методов. Выключить: собрать образ с
`--build-arg VITE_MOCK_FALLBACK=false`.

### Локально для разработки

```bash
npm install
npm run dev          # http://localhost:5173
```

## Обзор (UI-2)

- 4 карточки: пассажиров за день, пиковый час (ссылка на карту в этот час — `/map?hour=8`),
  маршрутов выше нормы, «Решения ждут диспетчера» (`GET /decisions?status=awaiting&status=updated`,
  считаются только основные решения, без альтернатив). Зелёный — только когда проблем нет.
- Карта (цвет — по самому загруженному часу маршрута), таблица «маршруты × часы», факторы дня.
- Методы решений требуют Bearer-токен роли «Диспетчер»; откуда его брать фронту, в контракте пока нет —
  без токена карточка покажет «Требуется авторизация». В моках решения строятся из прогноза.
- Подвал — источник данных, версия модели и время расчёта прогноза из `GET /health`.

## Карточка маршрута на Обзоре (UI-7)

- Справа от карты — список маршрутов (самые загруженные сверху, пик в пасс./ч и мини-график дня).
  Клик по маршруту в списке, на карте или в таблице открывает «Детализацию»; выбранный маршрут
  подсвечен, остальные на карте приглушены. Выбор хранится в адресе: `/?route=17`.
- Вкладки: «Пассажиропоток» (за день, трамваев и пассажиров на трамвай в пик, неделя по часам, пик
  с предупреждением), «График» (тот же, что на экране «Маршрут»), «Решения» (карточка решения).
- Карточка решения (`components/decisions/DecisionCard.tsx`) — проблема, предложение, эффект,
  проверка «одно депо» (БП-08), крайний срок; «Принять / Отклонить (с причиной) / В симулятор»,
  для принятого — «Исполнено / Не исполнено»; запасной вариант. Статусы — `PATCH /decisions/{id}`.
- В моках статусы решений хранятся до перезагрузки вкладки; переходы и ошибки — как в контракте (400, 404, 409).

## Решения (UI-8)

- Экран `/decisions` (`?route=17` — фильтр по маршруту): вкладки «Новые / Принятые / Отклонённые /
  Закрытые» со счётчиками; вкладка группы решений — по итогу всей группы (принят запасной вариант —
  «Принятые»). Сортировка — по крайнему сроку.
- Развёрнутое решение: графики «до / после» (пассажиров на трамвай по часам для маршрута и донора,
  линия нормы, интервал решения) и та же карточка решения, что на Обзоре.
- «После» считается из прогноза: `prediction / (trams_on_line ± trams_delta)` в интервале решения —
  поток неизменен (бизнес-правило).
- **Журнал** — только действия этой сессии (ответы `PATCH`): метода чтения `decision_log` в контракте нет.

## Маршрут без истории (UI-9)

- На экране «Маршрут» у маршрута с `is_new: true` (маршрут 5): предупреждение «Истории поездок нет»,
  «Похожие маршруты» (1, 7, 11, 12 — `ANALOG_ROUTES`, договорённость из CLAUDE.md) с их прогнозом на день,
  карта нового маршрута рядом с аналогами, ошибка метода аналогов из `GET /model/quality` (`method: analogs`).
- **Процент сходства — «—»:** в БД есть таблица `route_analog` (similarity, similarity_reason),
  но в контракте нет метода, который её отдаёт. Когда метод появится — перегенерировать типы
  (`npm run api:types`) и заменить `ANALOG_ROUTES` ответом API.

## Качество модели (UI-10)

- Экран `/quality`: MAE нашей и базовой модели по «Дню» и «Месяцу» (`GET /model/quality`), ошибка по
  маршрутам (горизонт — из шапки); у маршрута 5 столбиков нет — сноска с MAE метода аналогов.
- «Факт и прогноз» за 01–14.10.2025 по выбранному маршруту: `GET /actuals` + `GET /forecast` на те же
  даты и MAE за это окно. **Нужно от ML-8:** пакетный пересчёт должен писать в `forecast` и прогноз
  на проверочный период (сентябрь–октябрь), иначе API вернёт «Нет прогноза за выбранный период».
- **Важность факторов** — заглушка: её нет ни в БД, ни в контракте.

## Что если (UI-11)

- Экран `/what-if`: маршрут, часы (весь день, утро, день, вечер или интервал из решения), выходов
  на линии в пик. Считается сразу, без кнопки: `prediction / (trams_on_line ± Δ)` — поток неизменен
  (бизнес-правило), поэтому достаточно `GET /forecast`.
- График «исходный прогноз / сценарий» с коридором и нормой и три итога (часов выше нормы, максимум
  на трамвай, нужно выходов из резерва) считаются из одних и тех же точек.
- Параметры — в адресе: `?route=11&from=17&to=18&delta=1`; «В симулятор →» из карточки решения
  открывает сценарий этого решения.
- Погода, тип дня и событие — выключены: это пересчёт прогноза моделью, метода в контракте нет.

## Карта (UI-3)

- Цвет маршрута — **пассажиров на трамвай относительно нормы 150** (`PASSENGERS_PER_TRAM_NORM`):
  зелёный — до 80% нормы, жёлтый — 80–100%, красный — выше нормы, серый — трамваи не ходят. Один цвет на маршрут целиком.
- На экране «Карта» цвет — по выбранному часу шкалы (05 … 23, 00), «▶ Проиграть день» идёт по часам.
- На «Обзоре» маршрут красится по своему самому загруженному часу — поэтому красных маршрутов
  столько же, сколько в карточке «Маршрутов с пиковой нагрузкой» (с учётом списка «без координат»).
- Маршрут 5 — пунктир и метка «новый». Маршруты без координат (17, 25, 26, 28, 50) — списком под картой.
- Слой «Станции метро и МЦК» выключен: в контракте API нет метода со станциями.

## Маршрут (UI-4)

- «Дни × часы» и график дня строятся из одного запроса `GET /forecast` за месяц (горизонт `day`).
- Порог нормы на графике — `150 × trams_on_line` в пассажирах в час; участок выше порога — красный.
- «Неделю назад»: до 31.10 — факт (`GET /actuals`), позже — прогноз.
- Тип дня (выходной, праздник, перенос) — из `GET /factors` по каждой дате месяца.
- Блок «Показатели маршрута» ждёт метод API-7 — в контракте его пока нет.

## Месяц (UI-5)

- Горизонт «Месяц» на экране «Маршрут»: календарь месяца, график «Пассажиров в день», факторы месяца.
- Прогноз по дням — `GET /forecast?horizon=month` за ноябрь–декабрь (61 день, в пределах 62 по контракту);
  факт — `GET /actuals?granularity=day` за сентябрь–октябрь.
- Цвет клетки — от самого тихого дня месяца к самому загруженному. Клик по дню открывает его прогноз по часам.
- Погода месяца подписана: «прогноз погоды» или «климатическая норма» (без утечки из будущего).
- Обзор и Карта работают по часам одного дня — на «Месяце» они предлагают переключиться на «День».

## Экспорт и API (UI-6)

- Выгрузка `GET /export`: детализация (по часам / по дням), маршруты, период, CSV или XLSX; по умолчанию —
  весь период прогноза. Отдельная кнопка — формат сабмита (`route;date;hour;prediction`, 14 640 строк).
- Предпросмотр и пример запроса — настоящий запрос `GET /forecast` на первые строки файла.
- «Состояние сервиса» — `GET /health` (503 с телом `Health` показывается как состояние, а не ошибка).
- Производительность: до нагрузочного теста (OPS-3) — только цели организаторов, без выдуманных цифр.
- В мок-режиме XLSX скачивается как CSV — настоящий XLSX собирает бэкенд.

## Пустые состояния и ошибки (UI-13)

- Все запросы идут через `QueryView`: загрузка → «Загружаем данные…», 404 «нет данных» → спокойное сообщение
  с текстом из API, остальные ошибки → текст из поля `message` и кнопка «Повторить»; для `VALIDATION_ERROR`
  показываются `details` (какое поле неверно). Успешный ответ с пустым `items` — тоже «нет данных».
- Шапка проверяет `GET /health` раз в минуту: зелёный — только когда проблем нет, иначе оранжевый или
  красный индикатор с текстом.
- Ошибка отрисовки экрана не даёт пустую страницу (`ScreenErrorBoundary`).
- Повторяем только сетевые ошибки и 5xx; 4xx и «прогноз не рассчитан» — сразу показываем.

**Сценарии сбоев в мок-режиме** — добавь к адресу `?mock=<сценарий>` (запоминается на вкладку):

| Сценарий       | Что происходит                                          |
| -------------- | ------------------------------------------------------- |
| `offline`      | Сервер API недоступен (сетевая ошибка)                  |
| `not-ready`    | `503 FORECAST_NOT_READY`, `/health` без активной модели |
| `server-error` | `500 INTERNAL_ERROR` на всех методах                    |
| `empty`        | Пустой справочник маршрутов, 404 «нет прогноза / факта» |
| `no-geometry`  | `404 GEOMETRY_NOT_FOUND` для всех маршрутов             |
| `normal`       | Обычная работа (выключить сценарий)                     |

## Рабочий экран диспетчера (после Q&A 26.09)

- **Сплит на Обзоре:** слева карта (режимы «Пик дня» и «По часам» с «Проиграть день»), справа — сводка
  дня («Маршруты × часы» или список) либо развёртка выбранного маршрута. Карта не перезагружается.
- **Всё управление в шапке:** горизонт «День | Неделя | Месяц», дата со стрелками (на «Неделе» — по
  неделям), маршрут. Выбранный маршрут — общий контекст: на «Что если», «Решениях», экране «Маршрут»
  он тот же. Ссылка `/?route=17` открывает рабочий экран с маршрутом.
- **Путь маршрута:** день (показатели, график, решения) → неделя (7 дней по дням + «дни × часы») →
  месяц (календарь, график по дням). Клик по дню недели или месяца открывает этот день.
- Неделя — вид отображения: в API это `horizon=month` за пн–вс, контракт не меняется.

## Корректирующие коэффициенты (критерий 2в)

На «Что если» — ползунки «Погода» (−30…+30%), «Событие» (0…+50%), «Сезон» (−20…+20%). Поток сценария =
прогноз × (1 + погода) × (1 + событие) × (1 + сезон); вместе с изменением числа выходов пересчитываются
график, три итога и пассажиры за день. Значения — в адресе (`?weather=10&event=25`).

| --------------------------------- | ------------------------------------------------------------- |
| `npm run dev`                     | Dev-сервер                                                    |

## Структура

```
src/
├── api/            ← единственная точка доступа к данным
│   ├── types.ts    ← сгенерирован из docs/openapi.yaml — руками не править
│   ├── client.ts   ← getRoutes, getRouteGeometry, getForecast, getActuals, getFactors, exportForecast
│   ├── http.ts     ← fetch, параметры route=1&route=7, скачивание файлов
│   ├── errors.ts   ← ApiError: code + message из ответа API
│   └── config.ts   ← VITE_API_URL → мок-режим или API
├── mocks/          ← мок-«сервер»: те же ответы и ошибки, что в контракте
│   ├── handlers.ts
│   └── data/       ← маршруты, трассы, факторы, прогноз на 14.11.2025
├── config/         ← константы (норма 150, часы 05…00) и меню
├── context/, hooks/← фильтры шапки (День | Месяц, дата), запросы к API
├── components/     ← каркас, состояния (загрузка / пусто / ошибка), общие элементы
│   └── map/        ← карта MapLibre, шкала времени, слои, легенда
└── pages/          ← экраны
```

## Мок-данные

Строго по схемам `docs/openapi.yaml` (TypeScript проверяет каждый объект). Прогноз и факт считает
детерминированный генератор `src/mocks/data/forecast.ts` — одни и те же даты дают одни и те же числа.

- 10 маршрутов: 1, 5, 7, 11, 12, 17, 25, 26, 28, 50; маршрут 5 — `is_new: true`, прогноз `is_analog: true` с широким коридором, факта нет;
- трассы есть у 1, 5, 7, 11, 12 (координаты, кроме первых двух остановок маршрута 1, **условные**); для 17, 25, 26, 28, 50 — `404 GEOMETRY_NOT_FOUND`;
- прогноз «День» на 01.11–31.12.2025: 10 × 61 день × 24 часа = 14 640 строк (как `test_submission.csv`); «Месяц» — суммы по дням; строки маршрута 17 на 14.11 в 7 и 8 часов — точно из примера контракта;
- в будни у 11, 12, 26 в пик больше 150 пассажиров на трамвай; в выходные и праздники — ровнее и ниже; спад в предновогоднюю неделю;
- факт (`GET /actuals`) — сентябрь–октябрь 2025;
- факторы дня на любую дату сентября–декабря; 14.11 — точный пример контракта; погода — прогноз до 16.11, дальше климатическая норма. Особые дни 2025 (1, 3, 4 ноября, 31 декабря) и каникулы — сверить с таблицей DATA-5;
- ошибки — как в контракте: 404 с текстами из каталога ошибок, 400 при периоде длиннее 62 (прогноз) / 92 (факт) дней.
